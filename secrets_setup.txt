Secrets Management for Debian VPS & Docker Setup using Doppler

1. Method A: Host-Injected Secrets (No changes to Docker Image)
Keep the Docker image clean and let the Doppler CLI running on the Debian host inject the variables:

# Start container with host-injected secrets
doppler run -- docker run -d \
  --name my-app \
  -e DATABASE_URL \
  -e PORT \
  my-node-image:latest

*Note: Passing -e DATABASE_URL without a value tells Docker to securely forward the host's matching variable populated by Doppler in-memory.


2. Method B: Native Docker Compose Setup (Recommended)
You install the Doppler CLI inside your application's Dockerfile and set the DOPPLER_TOKEN as the only environment variable on your VPS host (e.g. in your docker-compose.yml file):

a) Dockerfile:
FROM oven/bun:latest
WORKDIR /app
# Install Doppler CLI inside the image
RUN apt-get update && apt-get install -y curl gnupg && \
    curl -sLf https://dl.doppler.com/public/cli/gpg.DE2A7741A397C129.key | gpg --dearmor -o /usr/share/keyrings/doppler-archive-keyring.gpg && \
    echo "deb [signed-by=/usr/share/keyrings/doppler-archive-keyring.gpg] https://packages.doppler.com/public/cli/deb/debian any-version main" | tee /etc/apt/sources.list.d/doppler-cli.list && \
    apt-get update && apt-get install -y doppler
COPY . .
ENTRYPOINT ["doppler", "run", "--"]
CMD ["bun", "server.js"]

b) docker-compose.yml:
services:
  web:
    build: .
    ports:
      - "6800:6800"
    environment:
      - DOPPLER_TOKEN=dp.pt.your_production_token_here
    restart: always
